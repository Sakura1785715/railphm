# 阶段 8.8 联动验收与演示闭环

## 演示前准备

- 启动 MySQL，并确认 `phm_device`、`phm_risk_result`、`phm_alert_record` 可正常读写。
- 启动 InfluxDB，并确认 `ATP001` 在演示时间段内有监测数据。
- 启动 `railphm-ai`。
- 启动 `railphm-server`。
- 启动 `railphm-web`。
- 可选：演示前清理 `ATP001` 的旧风险结果和告警，便于观察新增数据。

## 固定演示参数

- 设备编号：`ATP001`
- 结束时间：`2026-05-18 10:00:00`
- 回看时长：`60`
- 推理步长：`60`
- MC 采样次数：`20`
- 保存结果：`true`
- 生成告警：`true`

## 演示流程

1. 打开风险预测页。
2. 在“区间滚动推理”区域填入固定演示参数。
3. 点击“生成区间风险曲线”。
4. 检查本次风险曲线、健康度曲线、推理明细是否正常。
5. 检查告警统计、告警抑制窗口、本次生成告警、异常片段与抑制详情。
6. 点击“查看告警中心”，或手动进入告警中心。
7. 按设备编号 `ATP001` 查询，检查区间推理生成的新告警。
8. 打开一条告警详情，检查风险结果 ID、风险分数、健康度、健康等级、处理建议等字段。
9. 将一条告警更新为“处理中”或“已处理”。
10. 打开 Dashboard 或点击风险预测页的“刷新 Dashboard”入口。
11. 检查 KPI、风险趋势、健康度分布、最新告警、重点设备是否反映真实落库数据。
12. 使用同样参数重复执行区间推理，确认不会刷出大量重复告警，并能看到已有告警命中或抑制信息。

## 可选清理 SQL

仅供手动演示前使用，不要在程序中自动执行。

```sql
DELETE FROM phm_alert_record
WHERE device_code = 'ATP001';

DELETE FROM phm_risk_result
WHERE device_code = 'ATP001'
  AND window_end_time >= '2026-05-18 09:00:00'
  AND window_end_time <= '2026-05-18 10:00:00';
```

## 验收通过标准

- 风险预测页能生成 `risk_series` 和 `health_series`。
- `persist=true` 时风险结果写入 `phm_risk_result`。
- `generate_alert=true` 且 `persist=true` 时生成经过抑制的告警。
- 风险预测页能展示本次告警列表和异常片段与抑制详情。
- 告警中心能按设备、等级、状态筛选并查看新告警。
- 告警中心能将告警更新为“处理中”或“已处理”。
- Dashboard 能展示真实风险趋势、健康度分布、最新告警、重点设备和未处理告警 KPI。
- 重复执行同样参数不会生成大量重复告警。
- 页面无明显报错，空状态和跳过原因展示稳定。
